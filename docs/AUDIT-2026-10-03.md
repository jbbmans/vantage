# Audit and upgrade, 2026-10-03

An outside review of the live site (https://vantageusmc.com, build `cb9c4ac`, signed in as the owner) and of the code,
followed by the fixes. Every finding below was reproduced before it was fixed, and each fix has a regression test.

## How it was checked

- **Live site:** every route was signed in and opened at desktop and phone width. Console errors, failed requests, layout overflow and response headers were recorded. Only reads were sent to production.
- **Code:** reviewed for security, correctness and the interface. Each suspected bug was reproduced against a local, in-memory instance before being counted, and nothing was tested against production.
- **Accessibility:** axe ran on every page of the synthetic demo.
- **Competitors:** compared with official evaluation systems, military writing tools, and commercial work and performance platforms (below).

## Security

| | Severity | Finding | Fix |
|---|---|---|---|
| S1 | High | **One unauthenticated request could freeze the server.** A crafted 34-character password sent to `/api/auth/reset` (also register, invite and setup) took 4.5 s, and each extra digit roughly doubled that: the password-policy pattern backtracked exponentially. The same check runs on every keystroke in the browser. | The pattern is now a flat character class (`shared/password.ts`). |
| S2 | High | **A Marine could read entries they were not allowed to see.** A plain member (no "view shared records") could create a private goal "measured across the unit", filtered to one person. Its progress and contributors returned another team's shared entry titles and dollar amounts, while opening those entries directly was refused. | Measuring a whole unit now requires that permission, when the goal is set and every time it is read. A goal set before this (or by someone who lost the role) reads nothing. |
| S3 | Medium | **A sub-1 KB spreadsheet stalled the server for seconds.** The workbook reader's global lazy patterns rescanned to the end of the file from every unclosed `<row>` or attribute. | A forward scanner reads each element once (`server/lib/workbook.ts`): 2.6 s → 2 ms. It also now reads `numFmt` attributes in either order. |
| S4 | Medium | **Incoming email could stall the server.** The sanitizer copied the whole message once per tag, and the plain-text rendering rescanned for every unclosed `<script` or `<`. A 440 KB message took 12 s. | One lowercase copy, a single forward pass, a size cap and a nesting cap: 12 s → 20 ms. |
| S5 | Medium | **The lockout revealed which usernames exist, and a locked account had no self-service way out.** The third wrong password said "locked" for a real account and "incorrect" for a made-up one, and a reset link did not clear a lock for accounts with an authenticator. | A name with no account locks exactly as a real one does. A password reset clears the lock, and the lock message lists the ways back in. The three-strike lock itself stays: it is an accreditation control (AC-7). |
| S6 | Medium | **Rate limits keyed on the proxy chain.** Behind Cloudflare, every visitor reaching the site through the same Cloudflare edge could share one sign-in limit. | `VANTAGE_CLIENT_IP=cloudflare` takes the visitor's address from `CF-Connecting-IP`, but only when the peer is inside Cloudflare's published ranges, so a request that reaches the origin some other way cannot choose its address. It is set in `render.yaml`. |
| S7 | Low | **A slow Quick Log entry could freeze the user's tab.** Quick Log redid a full-text replace for every dollar amount (client only). | Done in one pass. |
| S8 | Low | **There was nowhere to report a vulnerability.** The site had no `security.txt` and no disclosure policy. | `/.well-known/security.txt` (RFC 9116, generated with a fresh expiry), a `/security` page with a safe-harbor policy, and an optional `VANTAGE_SECURITY_CONTACT`. |

The audit also checked these and found them well defended:

- direct record access by id
- dashboard, metrics, report and AI aggregation
- CSRF
- session rotation after password changes
- single-use, expiring reset and invite tokens
- OIDC
- server-side request forgery
- CSV formula injection
- `Cache-Control` on the API
- escalation through the owner console's import

## What was wrong with the live site

1. **`/governance` was broken outside the demo.** It opened an "Owner console" that called a demo-only API and showed "No such API route." It now returns a 404 outside the demo. The same applied to Support inside the demo, which returned 403s.
2. **Any unknown address showed bare, unstyled HTML.** The page said "VANTAGE" in a serif default font and had no way back into the app. Now someone signed in keeps the app around a "No page here" card with Search, and everyone else gets a branded 404.
3. **Several Today and Team states were empty or awkward.**
   - Today's "Who holds what" showed only its disclaimer when nobody held work.
   - Today read "0 items in your hands." and the queue read "You hold 0."
   - The Team goals card stretched to the height of the roster.
4. **Settings sat on a different left edge from every other page.** Its time zone menu also cut off its own label.
5. **Five file pickers had no accessible name.** On the record page this was a critical axe violation.
6. **The offline copy of the app could be the wrong page.** The service worker kept whatever page loaded last as the app's offline copy. After a visit to the public page, the app could not open offline, which is where Quick Log's offline mode lives. It now keeps only the application's own document.
7. **The site had no trust pages and almost nothing in its footer.** There was no security, privacy or accessibility page, and the footer held one button and a disclaimer.

`app.` and `console.` do not resolve yet; the address split is an owner step (`docs/deploy-render.md`). A ghosted unit badge seen in full-page screenshots is a screenshot artifact, not a defect.

## Correctness

The fixes are by `shared/` and `server/`, each with a test in `tests/server/auditFixes.*.test.ts`. They are listed by impact.

- **FITREP packages lost every Quick Log entry.** Quick Log saved JEPES area names, so for Sgt and above every entry fell into "Unassigned" and Section D showed 0. The period comparison showed every area empty.
- **Roster sync left people deactivated.**
  - A Marine dropped from one personnel extract stayed separated, with their account turned off, even after the next extract listed them again.
  - A row whose Status said "Separated" never turned an account off.
- **Quick Log put year-end work in the wrong fiscal year.**
  - It ignored "Sep 30", "September 30" and "last Friday", so the entry was dated today.
  - It read "$1.2 million" as $1.20.
  - It took "On 30 Sep 14 UDOs" as the year 2014.
  - It read "3/4 of the backlog" as March 4.
  - It merged the word after a count into its unit ("MIPRs after").
- **Amounts on the case form were dropped silently.** "1,118.38" was saved as nothing while the toast said it was recorded. Drafting a case action into your record also skipped the activity rules, so negative amounts and 31 February got in.
- **Plural units split into separate metrics.** "discrepancy" and "discrepancies" counted as different metrics, so goals missed entries.
- **Breakdowns were inconsistent.**
  - Per-area dollars included non-summable "reviewed" amounts.
  - Literal "Unassigned" entries were dropped.
- **The privacy rule on team totals could be defeated by subtraction.** A team with fewer than three contributors was withheld, but the command total minus the shown teams gave one person's figure.
- **The weekly digest counted at most 5 overdue tasks.**
- **Goal and FITREP countdowns were a day off in the evening.**
- **Imported email had several problems.**
  - Folded subjects gained stray spaces.
  - Raw UTF-8 headers came out as mojibake.
  - `addr (Name)` senders were misread.
  - Importing the same message twice created two threads.
- **Smaller problems:**
  - A due date accepted any string, so "10/15/2026" was overdue forever.
  - A private import with a unit set failed with a 500 after its preview said it would work.
  - The personal export's activities CSV had two "Visibility" columns, so it could not be imported back.

Two behaviour changes come with these fixes:

- **Status separations now count toward the roster's mass-separation guard.**
- **More team totals are withheld.** A command total is withheld when the entries outside its shown teams come from fewer than three people.

Two related problems are not fixed:

- **A first-sighting "Separated" row does not deactivate a matching account.** This is a person's first appearance in an extract, already marked Separated. On a first sync the guard has nothing to compare against.
- **Re-importing a document number can overwrite an existing case.** If a different report is keyed by the same document number in the same unit, it still overwrites that case.

## Look and feel

- **Public page:**
  - **Hero:** it now shows what a Marine gets (one sentence → an entry with its evidence → a FITREP line that cites it) instead of a finance case most junior Marines would not recognise. The finance case moved to the analysts section, where it belongs.
  - **New sections:** "Built for your role" (E-1–E-4, E-5+, leaders, financial management analysts, owners and ISSMs) and a speed-and-offline strip.
  - **Footer:** a real footer with product, trust and account links.
  - **Disclaimer:** it now says "not affiliated with, endorsed by or sponsored by".
- **New pages:** `/security` (including what to tell an ISSM, and the disclosure policy), `/privacy` and `/accessibility`. Each is prerendered, in the sitemap, and linked from sign-in and the footer.
- **Help form:** `/login?help` opens the help form directly, and `?help=security` opens it for a vulnerability report.

## Compared with similar products

Two groups were compared:

- **Military evaluation and writing tools:** A-PES/JEPES on MOL, the Semper Admin Portal, FITREP RS, RapidEPR, Army Leaders Book, AF myEval and NAVFIT.
- **Commercial work and performance platforms:** Lattice, 15Five, Linear, Asana, monday, Notion, and government AI hosts (Ask Sage, Game Warden).

**Where Vantage is ahead:**

- **Cited source records.** Bullets are drafted from attributed, sealed records. The writing tools work from free-form notes and send them to commercial AI.
- **Work and evaluation in one place.** Commercial tools split them across products.
- **Self-hosted.** It makes no third-party requests and supports CAC, Entra GCC High and an audit chain.
- **Privacy-preserving team views.**
- **Keyboard design** as good as Linear's.

**Where it fell short, and what was done:**

- **No trust pages.** Security, privacy, accessibility, `security.txt` and a vulnerability policy were added.
- **A hero aimed at analysts rather than the Marines it is sold to.** Rewritten.
- **No entry by role.** Added.
- **A weak disclaimer.** Strengthened.

**Recommended, not done:**

- **Demo link:** a separate demo host with a "Try the demo" call to action. Demo mode is refused in production, by design.
- **Changelog:** a public "What's new" page with the build version.
- **Founder story:** say that it was built in a Marine comptroller section.
- **Name and mark:**
  - **Trademark:** a legal check on using "USMC" in the brand and domain (Marine Corps Trademark Licensing).
  - **Name clash:** Palantir's "Army Vantage" shares the name.
- **Mobile navigation:** a bottom tab bar on phones.

## For the owner

- **Change the owner password.** It was shared in plain text during this review.
